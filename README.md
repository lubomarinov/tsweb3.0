# Aurum — злато-обезпечена сметка и карта

Маркетингов сайт на български **и** работещо демо на продукт, при който
клиентът държи салдото си в злато, а не във валута:

- зарежда евро → платформата купува инвестиционно злато по спот курса в същия момент;
- плаща с дебитна карта → продава се точно толкова метал, колкото покрива
  сметката, по курса в момента на авторизацията.

> **Демонстрационен проект.** Не е банка и не е лицензиран платежен институт.
> Котировките са симулирани и никакви реални средства не се движат.

## Стартиране

```bash
npm install
npm run dev      # локален сървър
npm test         # тестове на финансовата логика
npm run build    # продукционен билд в dist/
```

Сайтът е на `/`, демото — на `/#demo`.

## Архитектура

Кодът е нарязан така, че **финансовата логика да не знае нищо за React или
за браузъра**. Това е нарочно: същият `src/core/` се компилира непроменен в
React Native клиент за iOS и Android, а се сменя само слоят с изгледите.

```
src/
  core/         ← платформено-независим. Нула зависимости от DOM/React.
    money.ts      цели числа за пари (центове) и злато (микрограмове)
    goldPrice.ts  интерфейс за ценови поток + симулиран feed
    ledger.ts     чисти функции: зареждане, плащане с карта, продажба
    format.ts     bg-BG форматиране през Intl
    content.ts    текстовете на сайта (готови за превод/CMS)
    ledger.test.ts
  hooks/        ← тънък React слой над core (RN версията има свой еквивалент)
  components/   ← споделени UI части (икони, графика)
  marketing/    ← секциите на сайта
  demo/         ← интерактивният симулатор
```

### Защо цели числа

Пари се пазят в **евроцентове**, злато — в **микрограмове**. Float
аритметиката натрупва грешки от закръгляване, които в счетоводна книга се
проявяват като изчезващи стотинки. Закръглянето е нарочно асиметрично:

- издаденото злато при покупка се закръгля **надолу** — платформата никога не
  издава метал, който не е купила;
- продаденото злато при плащане се закръгля **нагоре** — покритието на
  сметката винаги е пълно;
- таксите се закръглят **нагоре** до цял цент, за да не могат серия
  микро-транзакции да ги заобиколят.

### Икономика на продукта

| Поток | Курс | Приход на платформата |
|---|---|---|
| Зареждане | ask (mid + спред) | спред 0,40% |
| Плащане с карта | bid (mid − спред) | спред + 0,5% над безплатния месечен оборот |
| Ръчна продажба | bid | спред + 0,25% |

Спредът се вижда в интерфейса преди всяко потвърждение. Веднага след покупка
портфейлът е „на минус" точно със спреда — това е коректно и е покрито с тест.

### Ценови поток

`GoldPriceSource` е интерфейсът, през който продукционният клиент се закача за
реален доставчик (LBMA fixing, борсов feed, Metals-API). Демото използва
`createSimulatedFeed()` — детерминирано случайно блуждаене със seed, за да са
възпроизводими графиката и тестовете. Смяната на доставчика не пипа нито един
друг файл.

## Път към мобилните приложения

`core/` и `hooks/` се преизползват дословно. За iOS и Android се пише само нов
изгледен слой (React Native компоненти вместо `div`/CSS), плюс:

- реален ценови поток през WebSocket вместо симулирания;
- сървърна счетоводна книга — `ledger.ts` става споделен валидатор между
  клиента и бекенда, а не единствен източник на истината;
- KYC, автентикация и карточен процесор.

## Какво още няма

Демото покрива продуктовата логика, не продукционна платежна система. Липсват:
регистрация и KYC, реално съхранение на метал и одит, сървърна книга и
сетълмент, интеграция с карточен процесор, обработка на chargeback-ове,
регулаторно съответствие.
